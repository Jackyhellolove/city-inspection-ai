# 城市巡查AI助手

## 国标问题目录与案件来源

新一阶段的案件来源和标准问题字典对齐现行 **GB/T 47678.5-2026《城市运行管理服务平台 第5部分：管理部件和事项》**（2026-07-01 实施，全部代替 GB/T 30428.2-2013）。本项目已依据标准附录 A 表 A.1 和附录 C 表 C.1 制作正式目录：153 条管理部件、250 条管理事项，共 403 条。

首次部署时，请依次在 Supabase SQL Editor 执行 `supabase-issue-dictionary.sql`、`supabase-issue-dictionary-v2.sql`、`supabase-gb47678.5-directory.sql`。若已执行过第一个文件，只需执行后两个。国标没有指定责任部门、优先级和完成期限；目录中的这些字段仅是待本地确认的建议值，后续可按本地权责清单维护。地方增补项必须标记为地方扩展，不能混作国标项。

已完成国标目录导入后，执行 `supabase-components-matters.sql` 可建立管理部件属性定义、管理事项属性定义、管理部件实例、管理事项实例，并为 `inspection_records` 增加行政区划、国标快照和部件/事项关联字段。该脚本已包含 `supabase-record-standard-fields.sql` 的字段变更；若前者尚未执行，只执行新脚本即可。

执行 `supabase-case-intake-config.sql` 可建立事项处置主管部门和单元网格配置，并为案件表增加主管部门代码、名称和所在单元网格字段。完成配置后，案件录入将只选择“管理事项”；下一阶段再以这些国标必填数据自动创建管理事项实例。

新案件录入以“管理部件 / 管理事项”为核心：人工描述、照片 AI 推荐和最终案件类型统一落到同一套国标目录。保存前必须由管理员确认一项国标条目，系统会将国标大类、标准号、五位代码和条目名称写入案件；执行 `supabase-record-standard-fields.sql` 后启用这些字段，同时启用“行政区划名称”和遵循 GB/T 2260 的六位行政区划代码。AI 未能准确匹配时会明确保留为“待人工选择”，不会把泛化的 AI 分类直接作为国标条目写入。

管理员登录后可从右上角菜单打开“标准问题字典”，下载 TSV 导入模板。导入时系统会校验标准号、代码、部件/事项类别、责任主体、优先级和时限；通过后以“标准号 + 部件/事项 + 标准代码”作为唯一键增量写入 Supabase。GB/T 47678.5-2026 的管理部件和管理事项都使用五位分类码，二者的同码条目不能互相覆盖。

## AI 调用与人工复核留痕

在执行完 `supabase-issue-dictionary.sql` 后，再执行 `supabase-ai-audit.sql`。它会为照片识别和城市态势研判建立调用历史、模型、耗时、Token 用量、脱敏结果摘要和管理员人工复核记录。审计表不保存现场照片、图片 Base64、完整提示词、访问令牌或 API 密钥；客户端没有修改和删除审计记录的权限。

驾驶舱的“AI 研判测试记录”优先读取该云端审计表；浏览器本机缓存仅作离线兜底。每次研判只能提交一次人工复核结论，复核写入后不可由客户端修改或删除。需要核验建表、RLS、策略和记录数时，可执行 `supabase-ai-audit-check.sql`，该脚本只读、不修改任何数据。

## 城管国标事项知识库

在已完成国标目录与 AI 留痕建表后，执行 `supabase-urban-knowledge-base.sql`。该脚本不会复制或修改 GB/T 47678.5-2026 国标目录，而是在其 250 条管理事项之上建立可维护的知识层：事项业务解释、处置与复核指引、同义词/地方叫法、视觉正反特征、易混事项及匹配留痕。

250 条国标管理事项仅建立知识主体，暂不批量填充未经验证的词语或规则。本阶段只建设 10 条高频事项：垃圾站（箱）满溢、暴露垃圾、积存垃圾渣土（承接“乱倒垃圾”）、道路不洁（承接“道路污染”）、占道经营、店外经营、乱堆杂物（承接“乱堆物料”）、违规户外广告、非法占绿毁绿（承接“绿地破坏”）和绿地脏乱（承接“绿化带垃圾”）。管理员可从右上角菜单进入“城管知识库”，逐步补充本地简称、照片特征和与相近事项的判别规则。照片 AI 或文字描述匹配后，系统保存候选事项、匹配方式、置信度和人工确认/修正结果；不保存图片 Base64、令牌或 API 密钥。

当前 V1 是“精确词＋可解释规则”匹配层。真实照片验收只统计人工复核后的“照片AI”记录：至少 50 张、每个高频事项至少 5 张，且推荐代码与人工最终确认代码一致率达到 80% 以上，才视为达到本阶段目标。待积累真实照片和人工复核样本后，再增加向量语义检索、视觉检测结果融合与大模型候选裁决，避免在缺少本地样本时直接固化不可靠规则。

高频知识包是否齐全、各事项样本量与总体准确率，可在完成一轮真实照片测试后执行 `supabase-urban-knowledge-base-check.sql` 查看；该脚本只读，不会修改案件或知识库数据。

### AI 识别复核提示

驾驶舱的 AI 复核队列除低置信度、待人工确认的结果外，也会提示“已有现场照片但未生成可靠目标框选”的案件。该提示仅用于提醒管理员重新识别或结合现场照片核对，不代表案件本身有误。

驾驶舱地图中的案件详情会在现场照片上同步展示已保存的 AI 框选区域，方便管理员直接对照文字结论与原始照片；框选仅作为辅助信息，仍需人工复核。

管理员可在驾驶舱案件详情中标记照片 AI “识别准确”或“需要修正”，修正时须填写原因。复核结论会保存到对应案件的 AI 数据中：已确认的结果不再进入 AI 复核清单，需修正的结果会持续提醒，形成模型效果评测闭环。

## 运行方法

### 桌面界面

在项目文件夹的终端中运行：

```bash
python3 app.py
```

输入巡查问题并点击“开始识别”，即可查看问题类型、处理部门和优先级。

如果 Mac 上的桌面控件显示不正常，请使用更稳定的浏览器版：

```bash
python3 web_app.py
```

启动后，终端会同时显示 Mac 地址和同一 Wi-Fi 下的手机访问地址。将手机访问地址输入手机浏览器即可预览；如 macOS 弹出网络访问提示，请选择“允许”。

浏览器版支持自动生成问题编号，记录发现地点、负责人和处置状态，并可保存历史记录和导出 CSV 表格。记录仅保存在当前浏览器中。

台账页面还支持状态统计、关键词搜索、按处置状态筛选和删除单条记录。

已保存的巡查记录可以继续编辑问题描述、发现地点、负责人和处置状态，系统会记录最后更新时间并实时刷新统计结果。

为防止浏览器数据被清理，页面支持将全部台账备份为 JSON 文件、从备份恢复新记录，以及直接打印巡查报告。

数据看板会实时展示问题总数、各处置状态数量、办结率、办结进度和问题类型分布。

每条巡查问题可设置完成期限，系统会自动显示即将到期和已逾期预警，并支持按期限状态筛选；已完成的问题不再计入逾期统计。

首页“时限督办”会汇总已逾期、48 小时内到期和待管理员核查的案件，点击指标可直接筛出相应台账；负责人登录时仅统计和展示本人被指派的待办。

管理员新建案件时，系统会依据“相同地点 + 相同问题类型”提示未结案的可能重复问题，便于合并派单或组织重点巡查；该提示不会阻止正常提交。

“责任人督办排行”按未结案待办、逾期和临期数量展示责任人，优先排列风险更高的待办；点击某位责任人即可筛出其案件。

管理员首页提供“核查队列”，集中列出待核查案件的负责人、最新处理说明、提交时间与整改凭证数量；点击“进入核查”即可办结或填写意见退回整改。

管理员在“待核查”节点选择“已结案”时，必须填写核查结论；选择“退回整改”时，必须填写退回整改意见。结论会随状态变化写入案件时间线，形成可追溯的核查留痕。

进入待核查案件的编辑窗口时，系统会汇总处置前现场照片、整改凭证数量和负责人最新提交说明，帮助管理员在办结前快速核对材料是否齐全。

案件编辑窗口会同步显示完成期限的剩余时间、临期或逾期风险；负责人办理时可据此优先处置，管理员调整期限或办结案件时也能即时看到对应的时限状态。

负责人登录后，首页会出现“我的待办”工作台，汇总本人待办理、退回整改和逾期案件；可一键筛选对应台账，或直接进入案件处理。

负责人提交办理结果后，案件会在“我的待办”中归入“待核查”，明确显示“等待管理员核查”；此时可查看案件详情和完整时间线，但不会再次显示为待办理，直到管理员退回整改。

被退回整改的案件会自动标示当前整改轮次；第 2 次及以上退回会标为“重点跟进”，并在管理员核查队列、负责人待办和案件详情中同步显示，便于优先处置反复问题。

管理员的“时限督办”新增“未设期限”指标，只统计未结案且尚未填写完成期限的案件；点击即可筛选台账并补齐期限，避免任务脱离时限管理。

管理员核查队列会显示负责人提交后等待核查的时长；超过 24 小时的案件会自动高亮为优先核查，帮助避免案件长期滞留在核查节点。

### 消息提醒与地图态势

右上角账户菜单中的“消息提醒”会基于当前登录人员自动汇总站内待办：负责人可看到逾期、临期和退回整改任务；管理员还可看到待核查超时及未设期限案件。点击提醒可直接进入对应案件处理或查看进度。

管理员可从右上角账户菜单进入独立的“城市一张图 · 领导驾驶舱”。驾驶舱集中展示案件总量、今日新增、处置中、待核查、逾期、办结率、责任人排行、问题热点和全域案件地图；点击地图点位可查看案件详情。尚未获取位置的案件不会展示在地图中。

领导驾驶舱新增近 7 日新增/办结趋势、问题类型占比和重点督办清单。重点督办会自动汇总逾期、两轮及以上整改和等待核查超过 24 小时的案件；点击清单可定位到地图点位并查看案件详情。

地图支持“案件点、点位聚合、热力态势”三种展示方式，并可按状态、问题类型和区域组合筛选。区域案件统计会从定位回填的“城市 · 区县 · 道路”地点文字中自动提取区县，展示案件总量、未办结、逾期和办结率；点击区域可联动筛选地图。

领导驾驶舱会订阅案件云端变化并自动刷新；实时连接异常时每 60 秒兜底同步一次，页面右上角显示连接状态和最近刷新时间。部门处置效能按责任部门汇总案件总量、未办结、逾期、办结率和平均办结用时；反复问题预警会识别同一地点、同一类型发生两次及以上的案件，并可联动地图筛选。

驾驶舱新增“数据治理清单”，按当前统计范围识别未定位、未设完成期限、未指派负责人、缺少现场照片和问题描述过短的案件。该清单不修改任何案件，只用于提示需要补齐的基础数据；点击任一项可返回巡查办理台并自动筛出对应案件。补齐后地图态势、时限督办、核查和 AI 研判的可信度会同步提升。

“专项治理建议”会根据重复发生、高发未办结、逾期与待核查积压的客观数据给出优先事项。点击建议可定位到地图或相应督办范围；它只做辅助决策，不会自动派单、修改案件或调用 AI。

领导决策简报会同步列出基础数据待补齐项和专项治理建议；因此即使不调用 AI，也能直接生成可打印的“事实—风险—行动”材料。

驾驶舱可生成“值班交接清单”，按当前统计范围汇总案件概况、需优先跟进的逾期/反复整改/超时待核查案件、数据缺项与专项治理提示。管理员可手动复制内容用于工作群或交接记录，生成和复制均不会改动案件。

管理员可在“治理规则”中自行设置重复发生次数、高发问题数量和待核查超时小时数。设置仅保存在当前浏览器，重点督办、反复问题预警、专项治理建议及值班交接清单会据此重新计算。

驾驶舱支持“大屏展示”，管理员可主动切换浏览器全屏，用于值班室或会议展示；进入或退出后地图会自动适配尺寸，不改变任何案件数据或当前筛选条件。

“处置时效运行监测”按实际创建、流转和办结时间展示平均办结用时、按期办结率、最长在办时长及核查积压；其中核查积压会随“治理规则”中的超时阈值同步调整。

地图支持按责任部门筛选；“部门处置效能”中的任一部门可点击下钻到地图，直接查看该部门当前范围内的案件分布和处置状态。

地图会显示当前生效的状态、类型、区域和责任部门筛选条件，并提供“一键清除筛选”，便于跨区域、跨部门联动分析后快速恢复全局视图。

点击驾驶舱地图中的案件详情，可使用“到办理台定位该案件”返回巡查办理台；系统会携带案件编号并自动填入搜索条件，便于直接打开详情、办理或核查。

“问题热点”和“反复问题预警”支持精确地点下钻：点击后会按发现地点和问题类型筛选地图，并在当前筛选条中显示地点条件；使用“一键清除筛选”即可返回全局态势。

“问题类型占比”支持类型下钻：点击任一类型会清除具体地点限定，并在地图中展示该类型在当前区域、部门和状态组合下的全部案件。

地图支持按负责人筛选；点击“责任人处置排行”中的任一人员，可下钻查看其案件的地图分布，并保留区域、部门、状态和类型等组合条件。

驾驶舱的“最长在办时长”和“核查积压”指标支持直接下钻地图：前者筛选全部未办结案件，后者按治理规则筛选超时待核查案件；手动调整地图筛选或点击“清除筛选”即可恢复常规展示。

驾驶舱右侧增加“临期督办”，实时列出未来 48 小时内到期且尚未办结的案件；点击任一案件可打开详情并在地图上定位。

地图案件详情会展示最近 4 条办理轨迹，包括状态变化、处理说明与时间；尚无进展时会明确提示，便于领导快速判断闭环情况。

从区域、热点、部门、负责人、类型和专项治理建议进入地图时，系统会自动清除“仅未办结”“核查积压”等上一次的专项条件，防止隐藏筛选干扰新的下钻结果。

地图区支持导出当前筛选结果为 CSV，导出内容严格遵循当前时间范围、状态、类型、区域、部门、负责人、地点及专项条件，便于形成临时督办清单。

地图案件详情支持按需加载原始现场照片：照片使用临时授权链接读取，点击可查看原图；无照片或授权读取失败时会给出明确提示并保留办理台入口。

负责人上传的整改凭证也会同步到地图案件详情，最多展示最近 6 张，便于在驾驶舱直接进行整改前后核查；若附件表暂未部署或无读取权限，不影响驾驶舱其他功能。

案件详情会复用已保存的照片 AI 辅助判断，展示风险、置信度、建议部门、建议处置和人工复核提示；该展示不会重新请求模型，也不会产生额外费用。

驾驶舱新增 AI 复核清单，自动列出置信度低于 70% 或分类、部门、风险仍待人工确认的识别结果，按置信度从低到高排序；点击可进入案件详情核对照片、AI 判断和办理材料。

驾驶舱顶部“处置提醒”会将当前时间范围内的逾期、超时待核查、临期和 AI 重点复核案件汇总为一个可点击清单，并按风险优先级排序；它仅生成站内辅助提醒，不会修改案件或发送外部通知。

近 7 日案件趋势支持按天点击下钻：地图会筛选该日发现的案件并显示当前日期条件，点击其他看板入口、手动调整筛选或清除筛选即可恢复常规展示。

“治理规则”支持设置 AI 复核置信度阈值（默认 70%，可设 50%～95%）；低于阈值或仍待人工确认的照片识别结果会进入 AI 复核清单与处置提醒。规则仅保存于当前浏览器。

数据治理清单增加“未 AI 研判”：统计已有现场照片但尚未生成照片 AI 辅助判断的案件，点击可返回办理台筛选补齐，便于掌握 AI 识别覆盖情况。

驾驶舱支持按最近 7 日、30 日、90 日或全部数据切换统计范围，地图、指标、区域、部门和风险清单同步变化。“生成领导决策简报”会自动形成运行态势研判、重点区域、部门效能和下一步处置建议，可直接打印或保存为 PDF 会议材料。

城市运行态势 AI 研判推荐使用阿里云百炼 `qwen3.7-plus`。该模型兼顾中文理解、复杂推理、长上下文与结构化输出，适合分析案件汇总并生成领导研判建议。态势研判默认复用照片识别的百炼 API Key，但使用独立的 `SITUATION_AI_MODEL=qwen3.7-plus`，不会把照片模型 `qwen3-vl-plus` 改掉；如需费用或权限隔离，也可单独配置 `SITUATION_AI_API_KEY`。

驾驶舱支持从服务器允许名单中切换态势研判模型。使用 `SITUATION_AI_MODEL` 指定默认模型，使用 `SITUATION_AI_MODELS` 按英文逗号列出可测试模型，例如 `SITUATION_AI_MODELS=qwen3.7-plus,qwen-plus`。页面不能自行输入名单外的模型，服务器也会再次校验，修改 `.env` 后需重启本地服务。模型会进入缓存指纹和评测历史，因此相同数据使用不同模型时不会错误复用缓存。

管理员点击“AI 智能研判”后，网页只向服务器发送问题类型、问题描述以及相同“类型 + 描述”的案件数量，不发送照片、案件编号、邮箱、账号 ID、负责人姓名或精确经纬度。服务器验证管理员身份后调用 `qwen3.7-plus`，返回总体判断、风险等级、重点发现、处置建议与数据注意事项；页面始终标注“AI 辅助研判，请人工复核”。

驾驶舱可自行选择“快速研判”或“深度分析”：快速研判关闭模型深度思考并限制输出长度，适合日常查看；深度分析开启模型深度思考，适合正式材料。页面会记住最近一次选择，并在结果和简报中显示本次模式及实际用时。

“查看送审数据”会在调用前逐项展示即将发送的问题类型、问题描述和数量，打开预览不会产生模型费用。相同模式、相同数据在 6 小时内再次研判会直接复用本机缓存并明确标注“未产生新费用”；数据或模式变化后会自动重新调用，也可在预览窗口手动清除缓存。

研判执行期间会实时显示“整理数据、验证管理员权限、通义千问分析、解析结果”四个阶段和累计等待时间。快速研判提示通常约 5～20 秒，深度分析提示通常约 20～60 秒；实际时间仍取决于网络和模型服务负载。

AI 结果默认处于“尚未复核”状态。管理员需先给本次结果选择 1～5 分效果评分，可选填写评分说明，再点击“确认采纳”或“标记需修正”。系统记录评分、说明、复核人和复核时间；只有确认采纳的结论才会进入领导决策简报，标记需修正时评分说明必填。复核信息随本地研判缓存保存，相同数据再次打开时仍可追溯。

“研判记录”会保存最近 20 次真实模型调用的生成时间、实际模型、模式、案件数、问题组数、耗时、输入/输出/总 Token、风险等级、人工评分、评分说明和复核状态，并分别计算快速研判与深度分析的平均耗时、平均 Token、平均评分，方便同时比较速度、资源消耗和实际效果。Token 数直接采用百炼接口返回的用量统计，不是前端估算。历史记录只保存在当前浏览器，不重复保存送审问题描述；查看历史结果不会调用模型，清空前会再次确认。

点击“导出评测 CSV”可把最近 20 次研判的实际模型、模式、统计范围、数据量、耗时、Token、风险等级、效果评分和人工复核信息导出为带中文表头的表格。导出只读取浏览器中已经保存的评测记录，不会调用模型，也不会包含送审的问题描述或照片。

研判记录顶部会按“实际模型＋快速/深度模式”形成评测卡片，展示调用次数、平均评分、平均耗时、平均 Token 和采纳率。每个候选组合至少获得 2 次人工评分后才参与横向推荐；推荐先比较人工平均评分，评分相同时再比较耗时和 Token，避免用不透明的综合分替代人工业务判断。

为了保证横向评测公平，可先打开“查看送审数据”，点击“锁定为评测样本”。固定后，即使案件数据或统计范围发生变化，切换模型和研判模式仍会使用完全相同的问题类型、问题描述和数量；页面会持续显示固定样本标识。样本只保存在当前浏览器标签页的会话存储中，关闭标签页或点击“解除固定样本”后清除。固定样本生成的 AI 结果只参与模型评测，不进入领导决策简报；自动推荐也只比较最近一组固定样本的记录。

固定样本启用后，“研判记录”会列出服务器开放模型与快速/深度模式的评测进度，每个组合目标为至少 2 次有效人工评分，并提示下一项建议。点击“选择此组合”或“再次测试”只会切换模型和模式、清除该页面当前研判缓存，不会自动调用模型；管理员仍需回到驾驶舱手动点击“AI 智能研判”才会产生调用和费用。

完成 AI 研判后再生成领导决策简报，简报会自动纳入同一统计时间范围的 AI 结论，并把“程序计算的统计事实”“规则生成建议”和“AI 辅助研判”分区展示。切换统计时间范围会自动清除旧研判，避免不同口径的结论混入同一份简报。

AI 智能研判不能在 `file:///.../command-center.html` 文件预览模式下调用。请先在项目目录运行 `python3 web_app.py`，再访问 `http://127.0.0.1:8000/command-center.html`；直接双击 HTML 仅用于查看静态页面。

如果提示 `latin-1 codec can't encode characters`，说明某个会写入 HTTP 请求头的 `.env` 配置仍是中文占位文字。重点检查 `SUPABASE_URL`、`SUPABASE_PUBLISHABLE_KEY`、`AI_API_KEY` 和 `SITUATION_AI_API_KEY`，必须填写控制台提供的真实英文、数字格式值；本地已有有效 `supabase-config.js` 时，服务会自动回退使用其中的公开配置。

填写并保存 `.env` 后，可先运行 `python3 web_app.py --test-situation-ai` 单独验证态势研判模型；该测试会产生一次很小的文本模型调用费用，不会调用照片识别模型。

驾驶舱优先使用高德地图 JS API 2.0。案件点位沿用巡查端采集的经纬度，并根据配置在展示时完成 WGS84 到 GCJ-02 的坐标转换；尚未配置高德 Key 或高德加载失败时，会自动切换到 Leaflet + OpenStreetMap 备用底图，保证本地测试时地图仍可操作。

巡查台账和案件详情会显示当前办理指引，明确当前责任方、要完成的操作及下一流转节点，减少跨角色协同中的状态判断成本。

案件详情中的“处置前后对比”将原始现场照片与负责人上传的整改凭证并列展示，可放大查看，便于管理员核查整改效果。

被退回整改的案件会在负责人处理窗口和详情页醒目展示管理员最近一次退回意见与时间，负责人无需翻找时间线即可按要求重新办理。

巡查记录支持添加一张现场照片：手机可直接调用相机拍摄，电脑可选择图片。照片会在保存前自动压缩，台账中显示缩略图并可点击查看大图，完整数据备份会同时包含照片。

每次修改处置状态时可以填写处理说明，系统会自动记录更新时间、原状态和新状态；点击台账中的“详情”按钮，可以查看问题完整信息和处置时间线。

### 处置闭环 V3

案件流程固定为“管理员新建并指派 → 负责人办理 → 管理员核查 → 已结案 / 退回整改”。管理员提交已指定负责人的案件后，案件直接进入“处理中”；负责人填写处理说明或上传整改凭证后点击“办理并提交核查”；管理员只在“待核查”节点选择办结或退回整改。退回案件由负责人重新办理后再次提交核查。

请在 Supabase SQL Editor 执行 `supabase-workflow-v3.sql`。该脚本会把历史“待接单”统一更新为“处理中”，将“已完成”更新为“已结案”，并在数据库层阻止跳过流程、非管理员建单、负责人越权或直接办结。

台账支持勾选当前筛选结果中的多条“待派单”记录，一次性指定负责人；批量派单同样会写入每条问题的处置时间线。

单条记录使用正式编辑窗口集中修改问题描述、地点、负责人、状态、完成期限和处理说明，不再需要连续操作多个浏览器提示框。

新增记录时可以获取设备当前位置，系统会将定位结果自动解析为道路名称并写入“发现地点”，同时保存经纬度；台账和详情窗口会提供地图查看入口，CSV 导出也包含坐标信息。定位统一使用 WGS84 坐标系：采集时会持续收敛到高精度 GPS 结果（而非基站/Wi-Fi 粗定位）并显示精度，避免 iPhone 等移动端因粗定位导致上图点位偏移；局域网 HTTP 预览受手机浏览器安全策略影响时，可继续填写文字地点，正式 HTTPS 版本可使用自动定位和道路名称回填。

巡查台账将问题编号与照片、描述与地点、类型与部门、负责人和状态、期限与更新时间分别合并为同类信息组。桌面端不再出现横向滚动条，中小屏幕会自动改为纵向记录卡片，所有原始字段仍完整保留。

新增带照片的巡查记录时，缩略图会直接使用本机压缩结果稳定显示；图片在后台上传至 Supabase Storage，同步状态只在原位置由“同步中”更新为“已同步”，不再重复刷新整张台账。其他账号产生的云端变更仍会自动合并刷新。

巡查报告支持填写报告名称、单位和编制人，自动使用当前筛选结果生成报告周期、统计摘要和签字栏，可通过浏览器打印或保存为 PDF。

项目已支持 PWA 安装和基础离线缓存：部署到 HTTPS 后，可在手机浏览器中添加到主屏幕；支持安装提示的浏览器会显示“安装应用”按钮。iPhone 可在 Safari 的分享菜单中选择“添加到主屏幕”。

当前版本已接入 Supabase 真实登录能力。请将 `supabase-config.example.js` 复制为 `supabase-config.js`，再填写项目 Settings > API 中的 Project URL 和 publishable key。该配置文件不会提交到 GitHub；不要填写 secret key 或 service_role key。

领导驾驶舱默认可直接使用 Leaflet + OpenStreetMap 备用底图。如需切换为更适合国内道路和地名展示的高德地图，可将 `amap-config.example.js` 复制为 `amap-config.js`，填写 Web Key 和安全密钥；浏览器定位数据默认为 WGS84，驾驶舱会在展示时转换为高德 GCJ-02 坐标。生产部署可设置 `AMAP_WEB_KEY`、`AMAP_SECURITY_JS_CODE` 和 `AMAP_COORDINATE_SYSTEM=WGS84`；如已配置高德推荐的服务端代理，可改设 `AMAP_SERVICE_HOST`，且不再提供 `AMAP_SECURITY_JS_CODE`。

运行 `supabase-profile-bootstrap.sql` 后，已验证账号会自动补齐人员资料；新注册账号在邮箱验证前不会进入负责人派单名单，验证完成后自动转为在岗。这样可避免误填邮箱产生的未验证账号被派单。

登录页支持“忘记密码”：填写注册邮箱后点击该按钮，按邮件链接返回页面设置新密码。请在 Supabase Authentication 的 Redirect URLs 中加入实际访问地址；本机测试至少加入 `http://127.0.0.1:8000/index.html`，局域网或正式 HTTPS 地址也需分别加入。

巡查记录云端同步启用后，新增、编辑、批量修改和删除会同步到 Supabase 的 `inspection_records` 表；首次登录会读取当前账号有权限查看的云端台账。要让已打开的手机和 Mac 页面自动刷新，请在 Supabase SQL Editor 中运行 `supabase-realtime.sql`。

运行 `supabase-timeline.sql` 后，创建记录、编辑记录和批量处理产生的状态变化及处理说明会写入 `inspection_updates` 表；问题详情将从云端读取并展示完整处置时间线。

运行 `supabase-photos.sql` 后，新增巡查记录时选择的现场照片会压缩后上传至私有的 Supabase Storage 桶。巡查员只能查看自己上传的照片，管理员可查看全部照片；换设备登录后照片仍可显示。

巡查编号采用日期加随机标识生成，避免不同设备同时录入时发生重复。云端短暂不可用时，记录会暂存本机，并在下次打开页面后自动重试同步。

运行 `supabase-attachments.sql` 后，可在编辑记录时一次选择最多 6 张整改凭证照片；每条记录可分多次持续追加，详情页按时间展示照片、处理说明和上传时间。

运行 `supabase-assignees.sql` 后，管理员登录时会从已注册账号读取在岗负责人名单，用于新建、编辑和批量派单；台账可按负责人筛选，并在看板显示各负责人的未完成待办数量。

运行 `supabase-user-management.sql` 后，管理员可在系统内维护已注册账号的部门、角色和在岗状态；停用账号会从负责人派单名单中移除。

运行 `supabase-assignee-access.sql` 后，派单会关联具体账号；负责人登录后可查看和更新分配给自己的巡查记录，管理员仍可管理全部记录。

负责人界面只提供任务详情、处置状态、处理说明和整改凭证操作；基础问题信息、负责人、期限、批量派单和删除由管理员维护。

运行 `supabase-assignee-field-protection.sql` 后，上述限制同时在数据库层生效：负责人即使绕过网页直接调用接口，也只能修改本人任务的处置状态，不能修改基础字段或删除记录。

负责人看不到已派任务时，请先以管理员登录，在人员管理中确认该账号为“在岗”，再重新选择该负责人并保存任务。随后在 Supabase SQL Editor 依次再执行 `supabase-assignee-access.sql`、`supabase-timeline.sql`、`supabase-attachments.sql` 和 `supabase-photos.sql`，以补齐历史任务的账号关联和负责人的时间线、凭证、现场照片访问权限；同名账号不会自动关联，需使用唯一的显示姓名。

### 现场照片 AI 识别（本机试用版）

运行 `supabase-ai-analysis.sql` 后，照片 AI 的分类、风险、建议和置信度会随巡查记录保存到云端。它仅用于辅助判断，保存前仍应结合现场情况人工复核。

为保护 API 密钥，浏览器不会直接调用 AI 服务。请在项目文件夹中完成以下一次性配置：

```bash
cp .env.example .env
```

随后用 VS Code 打开 `.env`，只在本机填写 API 密钥。不要把密钥发到聊天、截图中，或提交到 GitHub。

照片 AI 支持通过 `.env` 切换供应商：`AI_PROVIDER=openai` 使用 OpenAI，`AI_PROVIDER=dashscope` 使用阿里云百炼的通义千问视觉模型，`AI_PROVIDER=compatible` 可接入任何兼容 OpenAI Chat Completions 且支持图片输入的服务。统一填写 `AI_API_KEY`、`AI_MODEL`，第三种方式另需填写 `AI_BASE_URL`。每次切换后重启 `python3 web_app.py`。例如，可先用 `dashscope` 与 `qwen3-vl-plus`；DeepSeek 在未来提供适合的视觉模型和兼容接口后，只需改为 `compatible` 并填入其地址与模型名，无需修改代码。

完成配置后，使用下面的命令启动网页（不要再用 `python3 -m http.server`）：

```bash
python3 web_app.py
```

选择或拍摄一张现场照片，再点击“AI 识别现场照片”。网页会把照片交给 Mac 上的本地服务转发，密钥始终只由本地服务读取；识别结果会显示为“请人工复核”。

照片 AI 识别完成后，系统会将 AI 生成的现场问题描述自动写入“巡查问题”输入框，便于直接保存；保存前仍可由巡查人员修改和复核。

每次切换供应商或模型后，可以在正式启动网页前先执行以下命令。它会发送一张极小的测试图片，验证密钥、模型、视觉能力和返回格式，成功后自动退出；这会产生一次模型调用费用：

```bash
python3 web_app.py --test-ai
```

驾驶舱中的“待核查”和“已逾期”核心指标支持直接下钻至城市一张图：前者按案件状态筛选，后者按完成期限筛选，同时保留当前的区域、部门、负责人和问题类型条件。

城市一张图下方会同步展示当前筛选案件清单，优先排列逾期、核查积压、临期和退回整改案件；点击任一案件即可查看完整详情并定位点位。

处置提醒可导出为督办清单 CSV，清单包含提醒等级、责任部门和负责人、期限状态、地点以及建议督办动作；导出仅生成本地文件，不会改变案件状态或发送外部通知。

城市一张图的搜索框支持按巡查编号、问题描述、发现地点、责任部门、负责人或问题类型快速筛选，并可与状态、区域等条件叠加使用。

管理员可主动开启驾驶舱的浏览器提醒。仅在页面保持打开、浏览器已授权通知且出现新的逾期、核查积压、临期或 AI 复核事项时提示；默认关闭，不发送短信、邮件或任何外部消息。

## HTTPS 部署

项目包含照片 AI 的 Python 服务，不能只部署为静态网站。仓库已提供 `render.yaml`，可在 Render 创建 Blueprint/Web Service；平台会自动提供 HTTPS。部署时在服务环境变量中填写 `AI_API_KEY`、`SUPABASE_URL` 和 `SUPABASE_PUBLISHABLE_KEY`；如启用高德地图，再填写 `AMAP_WEB_KEY` 及高德安全配置。不要提交 `.env`、secret key 或 service_role key。部署完成后，还需把正式 HTTPS 地址加入 Supabase Authentication 的 Site URL/Redirect URLs；启用高德时同时把域名加入高德 Web Key 白名单。
